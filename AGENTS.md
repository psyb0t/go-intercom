# go-intercom

Unofficial Go client for the Intercom REST API, generated from the OpenAPI document Intercom publishes. If you only want to use the client from an agent, read [.agents/skills/go-intercom/SKILL.md](.agents/skills/go-intercom/SKILL.md) instead; this file is about changing the code.

## Architecture

One generated package, `intercom`, at the module root, driven by `gen.go`:

`scripts/fetch-spec.sh` selects the newest numbered stable version under `intercom/Intercom-OpenAPI/descriptions`, skipping `0` and previews, and downloads its `api.intercom.io.yaml` to `api/openapi.yaml`. `scripts/patch-spec.sh` runs the YAML tool under `internal/cmd/patch-spec/` to write `api/openapi.fixed.yaml`. oapi-codegen reads the patched document with `config.yaml` and writes `client.gen.go`. `scripts/split-gen.sh` splits it into `client_*.gen.go` at declaration boundaries and removes unused imports with goimports.

## Stack

- Go 1.26.9.
- oapi-codegen v2.8.0, pinned as a `tool` dependency in `go.mod`.
- Runtime: `github.com/oapi-codegen/runtime`.

## Layout

- `gen.go`, `config.yaml`, `client_*.gen.go`: the package.
- `client_test.go`, `example_test.go`: tests, including the README example.
- `scripts/`: spec download and patch, lint and security scan scripts.
- `internal/cmd/patch-spec/`: the YAML spec patch tool.
- `api/`: the downloaded spec, gitignored.
- `vendor/`: committed, regenerated by `make dep`.

## Dev workflow

Everything runs in the `Dockerfile.dev` image. You need Docker and Make.

```bash
make dep       # go mod tidy + go mod vendor
make generate  # download the spec and regenerate
make lint      # shellcheck, shfmt, go fix, golangci-lint
make test      # go test -race
make sec       # gitleaks, govulncheck, semgrep
```

## Project-specific landmines

- The initial spec is Intercom API 2.17, OpenAPI 3.0.1. It contains 258 HTTP operations across 182 paths. Generate all operations.
- Reporting export status and download paths omit their `job_identifier` parameter declarations. The patch adds required string path parameters before generation; without it oapi-codegen rejects the spec.
- Inline `type` enums on `conversation_attribute_list` and `ticket` collide with component Go names. The patch sets `x-go-type-name` to `ConversationAttributeListObjectType` and `TicketObjectType`. JSON field names and enum values stay unchanged.
- Contact create and update bodies wrap a single component reference in `oneOf`. The resulting body types lose their JSON marshaling methods and send `{}`. The patch replaces those wrappers with direct references; POST and PUT tests check the serialized fields.
- Other inline request unions, for Fin escalation, conversation parts, tags and ticket replies, move unchanged into named components. Referencing those components makes request body aliases retain JSON methods. The union round-trip tests check each operation and both Fin identifier forms.
- The config maps `number` to `float64`, prefixes enum values and resolves type name collisions.
- Authentication is bearer auth, attached through `WithRequestEditorFn`. Pin `Intercom-Version: 2.17` when using these generated models. The optional header otherwise follows the app's configured version.
- Workspace regions use different hosts: `api.intercom.io`, `api.eu.intercom.io` and `api.au.intercom.io`.
- Method names follow operation IDs, with generated path names for reporting endpoints that lack an operation ID.
- Pagination differs by endpoint. `ListContactsParams` omits cursor fields despite the operation's pagination description; use a request editor to add query fields when needed.
- `make generate` always downloads the current stable spec, so it can change the client even when nothing here changed. Review the generated diff.
- `.github/workflows/regen.yml` regenerates the client every day and releases the result. When the checks fail, Claude edits the repository to fix them, but a fix may not touch the paths listed under `fix_protected_paths` in that workflow: the workflows, the Makefile, `AGENTS.md`, `.agents/rules/`, the lint, security and spec download scripts and their configs. A problem that needs a change there fails the run and needs a manual fix.
